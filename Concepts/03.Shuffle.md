What actually happens during shuffle

When a wide transformation (like groupBy, join) happens:

1. Data is redistributed
Records are moved across partitions based on key
2. Intermediate shuffle files are created
Data is temporarily written to local disk (on executors)
This is called shuffle spill / shuffle files
3. Next stage reads this data
Executors fetch required partitions over the network
Then computation continues

✅ Correct thinking:
Only intermediate shuffle data is written (if needed)
Spark tries to keep data in memory as much as possible
Disk is used only when:
Data is large
Memory is insufficient
Shuffle requires persistence
🎯 Why disk is involved at all

Because during shuffle:

Data must survive between stages
Executors may not have enough memory
Data needs to be fault-tolerant

So Spark uses:

Memory (preferred)
Disk (fallback via shuffle files)
